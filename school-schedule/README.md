# Школьное расписание с заменами

Сайт, на котором ученики и родители смотрят расписание своего класса и все изменения в нём,
а учителя и завуч вносят замены через защищённую панель.

- **Для учеников (без входа):** выбираешь класс один раз (запоминается на устройстве) — и сразу видишь
  уроки на сегодня и на следующий учебный день. Замены выделены цветом и подписаны прямо в списке
  (замена учителя, другой предмет, другой кабинет, отмена, перенос). Вверху — «обновлено в ЧЧ:ММ».
- **Для учителей (вход по логину и паролю):** список замен и кнопка «Добавить замену»; можно изменить или
  удалить свою запись. Внизу — сворачиваемая «История изменений» (кто и когда что менял).
- **Для администратора (завуча):** три вкладки — «Замены», «Расписание» (постоянное) и «Настройки»
  (школа и звонки, классы, учителя, предметы, кабинеты, пользователи, журнал — в сворачиваемых блоках).
- Мобильная версия в первую очередь, тёмная тема, интерфейс на русском.
- Изменения видны всем сразу после сохранения (страница сама обновляется раз в минуту и при возвращении на страницу).
- Изменения на прошедшие даты скрываются автоматически (в журнале остаются).

**Технологии:** Python 3.10+, FastAPI, SQLite (один файл базы, отдельный сервер БД не нужен),
обычные HTML/CSS/JavaScript без сборки. Зависимостей всего три: `fastapi`, `uvicorn`, `tzdata`.

## 1. Структура файлов

```
school-schedule/
├── app/                     серверная часть
│   ├── main.py              запуск приложения, заголовки безопасности, понятные ошибки
│   ├── config.py            настройки (читаются из файла .env)
│   ├── db.py                схема базы данных SQLite
│   ├── security.py          пароли, сессии, защита от подбора пароля, CSRF
│   ├── schemas.py           проверка всех вводимых данных
│   ├── schedule.py          сборка расписания: постоянное + замены на дату
│   ├── audit.py             журнал действий
│   ├── seed.py              пример данных
│   └── routes/
│       ├── public.py        открытое API: список классов и расписание
│       ├── auth.py          вход, выход, смена пароля
│       ├── changes.py       замены и журнал (учителя и администраторы)
│       └── admin.py         справочники, расписание, звонки, пользователи (только администратор)
├── static/                  то, что видит браузер
│   ├── index.html           страница для учеников и родителей
│   ├── admin.html           панель учителя / завуча (адрес /admin)
│   ├── css/style.css        оформление (тёмная тема, мобильная вёрстка)
│   └── js/                  common.js, app.js (сайт), admin.js (панель)
├── deploy/                  файлы для сервера: systemd, Caddy, резервное копирование
├── tests/                   автоматические тесты
├── manage.py                служебные команды: база, пример данных, администратор, сброс пароля
├── requirements.txt         зависимости
└── .env.example             пример файла настроек
```

База данных создаётся автоматически в `data/schedule.db`.

## 2. Запуск на своём компьютере

Нужен **Python 3.10 или новее**. Проверить: `python --version` (на Windows — `py --version`).
Скачать: <https://www.python.org/downloads/> (на Windows при установке отметьте «Add Python to PATH»).

### Шаг 1. Получить код

Если установлен git:

```bash
git clone -b claude/school-schedule-website-vnhfmh https://github.com/InTAnChIK/claude-code.git
cd claude-code/school-schedule
```

Или скачайте архив ветки на GitHub (кнопка **Code → Download ZIP**), распакуйте и откройте папку `school-schedule`
в терминале.

### Шаг 2. Установить зависимости

**Windows (PowerShell):**

```powershell
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

После `activate` в начале строки терминала появится `(.venv)` — так и должно быть.
Во всех следующих командах окружение должно быть активно.

### Шаг 3. Загрузить пример данных (по желанию)

```bash
python manage.py seed
```

Появятся школа «МБОУ «Средняя школа № 1»», классы **5А, 7Б, 9В**, 13 учителей, предметы, кабинеты,
8 уроков со звонками, полная неделя расписания (пн–пт) и 5 замен на ближайшие учебные дни
(по одной каждого типа). Команда сработает только на пустой базе — существующие данные она не трогает.

Чтобы начать с чистого листа, пропустите этот шаг: всё можно завести в панели.

### Шаг 4. Создать администратора

```bash
python manage.py create-admin
```

Подробнее — в [следующем разделе](#3-как-создать-первого-администратора).

### Шаг 5. Запустить

```bash
uvicorn app.main:app --reload
```

Откройте в браузере:

- <http://127.0.0.1:8000> — сайт для учеников;
- <http://127.0.0.1:8000/admin> — панель учителя.

Остановить сервер: `Ctrl+C`.

> Чтобы посмотреть сайт с телефона в той же Wi-Fi-сети, запустите
> `uvicorn app.main:app --host 0.0.0.0` и откройте `http://<IP-адрес компьютера>:8000`.
> Это только для проверки: в интернет сайт выкладывается по HTTPS (раздел 5).

### Тесты (по желанию)

```bash
pip install -r requirements-dev.txt
python -m pytest
```

## 3. Как создать первого администратора

Администратор (завуч) создаётся командой в терминале — так никто посторонний не сможет «занять» эту роль
через сайт.

```bash
python manage.py create-admin
```

Программа спросит:

1. **Логин** — латинские буквы, цифры, точка, дефис, подчёркивание (3–32 символа), например `zavuch`;
2. **ФИО** — например `Петрова Ирина Сергеевна`;
3. **Пароль** — минимум 8 символов, вводится дважды. При вводе символы не отображаются — это нормально.

Можно сразу указать логин и ФИО:

```bash
python manage.py create-admin --username zavuch --name "Петрова Ирина Сергеевна"
```

Дальше администратор заходит на `/admin` и создаёт остальных пользователей (учителей и других администраторов)
в «Настройках» → **«Пользователи»**.

**Забыли пароль или учётная запись заблокирована после неудачных попыток?**

```bash
python manage.py reset-password --username zavuch
```

Команда задаст новый пароль, снимет блокировку и завершит все открытые сеансы этого пользователя.

## 4. Первые шаги в панели

Войдите на `/admin` как администратор.

1. **«Настройки» → «Школа и звонки»** — название школы, учебные дни (пн–пт или пн–сб) и время каждого урока.
2. **«Настройки» → «Классы», «Учителя», «Предметы», «Кабинеты»** — заполните списки.
3. **«Расписание»** — выберите класс и день недели, нажмите «Добавить» у нужного урока.
4. **«Настройки» → «Пользователи»** — заведите учителей с ролью «Учитель».

Замену вносят кнопкой **«+ Добавить замену»**: дата → класс → урок (форма сразу покажет,
какой урок стоит по расписанию) → «Что случилось» → одно нужное поле → комментарий по желанию.

| Тип | Что обязательно указать |
|---|---|
| Замена учителя | нового учителя |
| Другой предмет | новый предмет (учитель — по желанию; так же можно добавить урок в пустое окно) |
| Смена кабинета | новый кабинет |
| Отмена урока | ничего, только по желанию комментарий |
| Перенос | дату и номер урока, куда переносится (время должно быть свободно) |

Учитель может редактировать и удалять только свои записи, администратор — любые.
Все действия попадают в журнал (у учителя — «История изменений» под списком, у завуча — «Настройки» → «Журнал действий»).

## 5. Размещение на хостинге (пошагово)

Ниже — самый надёжный и недорогой способ: свой виртуальный сервер (VPS) с Ubuntu, веб-сервер
**Caddy**, который сам получает и продлевает HTTPS-сертификат, и служба **systemd**, которая
перезапускает сайт после сбоев и перезагрузок.

Понадобится:

- **VPS** с Ubuntu 22.04 или 24.04 (хватит самого маленького тарифа: 1 ядро, 1 ГБ памяти) у любого
  хостинг-провайдера. После покупки у вас будет IP-адрес сервера и пароль (или SSH-ключ) пользователя `root`;
- **домен** или поддомен, например `raspisanie.school1.ru` (часто школе может выделить поддомен тот,
  кто обслуживает её основной сайт).

### Шаг 1. Направить домен на сервер

В панели управления доменом (DNS) добавьте запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `raspisanie` (или `@` для основного домена) | IP-адрес вашего сервера |

Изменение DNS вступает в силу от нескольких минут до нескольких часов.

### Шаг 2. Подключиться к серверу

На Windows откройте PowerShell, на macOS/Linux — Терминал:

```bash
ssh root@IP-адрес-сервера
```

Все дальнейшие команды выполняются на сервере.

### Шаг 3. Установить программы

```bash
apt update && apt upgrade -y
apt install -y python3 python3-venv git sqlite3 debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy
```

(Команды для Caddy взяты из официальной инструкции: <https://caddyserver.com/docs/install#debian-ubuntu-raspbian>.)

### Шаг 4. Включить брандмауэр

```bash
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw --force enable
```

Порт 8000 наружу **не открываем**: сайт будет доступен только через Caddy по HTTPS.

### Шаг 5. Скопировать код и установить зависимости

```bash
useradd --system --home /opt/school-schedule --shell /usr/sbin/nologin schedule
git clone --depth 1 -b claude/school-schedule-website-vnhfmh https://github.com/InTAnChIK/claude-code.git /tmp/src
cp -r /tmp/src/school-schedule /opt/school-schedule
rm -rf /tmp/src
cd /opt/school-schedule
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
nano .env        # проверьте часовой пояс SCHOOL_TZ; сохранить: Ctrl+O, Enter; выйти: Ctrl+X
```

### Шаг 6. Подготовить базу и создать администратора

```bash
cd /opt/school-schedule
mkdir -p data && chown schedule:schedule data
chown root:schedule .env && chmod 640 .env
sudo -u schedule .venv/bin/python manage.py init-db
sudo -u schedule .venv/bin/python manage.py seed            # только если нужен пример данных
sudo -u schedule .venv/bin/python manage.py create-admin
```

> **Важно:** на сервере все команды `manage.py` запускайте именно так —
> `cd /opt/school-schedule && sudo -u schedule .venv/bin/python manage.py ...` — от имени пользователя `schedule`.
> Если запустить их от `root`, служебные файлы базы могут стать недоступны сайту.

### Шаг 7. Запустить сайт как службу

```bash
cp /opt/school-schedule/deploy/school-schedule.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now school-schedule
systemctl status school-schedule      # должно быть «active (running)»; выйти — клавиша q
```

### Шаг 8. Включить HTTPS через Caddy

```bash
cp /opt/school-schedule/deploy/Caddyfile /etc/caddy/Caddyfile
nano /etc/caddy/Caddyfile             # замените raspisanie.example.ru на свой домен
systemctl reload caddy
```

Через минуту откройте `https://ваш-домен` — должен открыться сайт с замком в адресной строке.
Сертификат Caddy получает и продлевает сам; запросы по `http://` автоматически перенаправляются на `https://`.

### Шаг 9. Проверить

- `https://ваш-домен` — выберите класс, посмотрите расписание;
- `https://ваш-домен/admin` — войдите администратором и создайте учителей.

Если что-то не работает, смотрите журналы:

```bash
journalctl -u school-schedule -n 50     # ошибки сайта
journalctl -u caddy -n 50               # ошибки HTTPS (чаще всего — DNS ещё не обновился)
```

> **Другие варианты хостинга.** Подойдёт любая площадка, где можно запустить Python-приложение
> и есть **постоянный диск** для файла базы (на «бесплатных» облачных тарифах файлы часто стираются
> при перезапуске — данные пропадут). Команда запуска:
> `uvicorn app.main:app --host 0.0.0.0 --port $PORT`; если площадка сама даёт HTTPS, в `.env`
> оставьте `COOKIE_SECURE=auto` или поставьте `COOKIE_SECURE=1`.

## 6. Обновление и резервные копии

### Резервные копии

Все данные — в одном файле `data/schedule.db`. Ежедневная копия (хранятся 30 дней):

```bash
chmod +x /opt/school-schedule/deploy/backup.sh
crontab -e
```

Добавьте строку (копия каждый день в 03:15):

```
15 3 * * * /opt/school-schedule/deploy/backup.sh
```

Копии лежат в `/var/backups/school-schedule/`. Время от времени скачивайте их к себе:
`scp root@IP-адрес:/var/backups/school-schedule/*.db .`

Восстановление: `systemctl stop school-schedule`, удалить `data/schedule.db-wal` и `data/schedule.db-shm`
(если есть), скопировать нужную копию на место `data/schedule.db`, выполнить
`chown schedule:schedule /opt/school-schedule/data/schedule.db`, затем `systemctl start school-schedule`.

### Обновление кода

```bash
/opt/school-schedule/deploy/backup.sh
git clone --depth 1 -b claude/school-schedule-website-vnhfmh https://github.com/InTAnChIK/claude-code.git /tmp/src
cp -r /tmp/src/school-schedule/app /tmp/src/school-schedule/static /tmp/src/school-schedule/manage.py /opt/school-schedule/
cp /tmp/src/school-schedule/requirements.txt /opt/school-schedule/
rm -rf /tmp/src
/opt/school-schedule/.venv/bin/pip install -r /opt/school-schedule/requirements.txt
systemctl restart school-schedule
```

Папка `data/` и файл `.env` при этом не затрагиваются.

## 7. Безопасность

| Требование | Как сделано |
|---|---|
| Хеширование паролей | `scrypt` со случайной «солью» для каждого пароля; пароли нигде не хранятся в открытом виде |
| Защита от SQL-инъекций | все запросы к базе — параметризованные (значения передаются отдельно от текста запроса) |
| Защита от XSS | браузерная часть вставляет данные только как текст (никакого `innerHTML`); строгая политика CSP запрещает чужие и встроенные скрипты |
| Ограничение попыток входа | 5 неудачных попыток на логин или 20 с одного IP-адреса за 15 минут — дальше вход временно закрыт; ответ «неверный логин или пароль» одинаков для несуществующих пользователей |
| HTTPS | Caddy с сертификатом Let's Encrypt, перенаправление с http, заголовок HSTS; cookie входа с флагами `Secure`, `HttpOnly`, `SameSite=Strict` |
| Подделка запросов (CSRF) | каждое изменение данных требует секретный токен сеанса в заголовке `X-CSRF-Token` |
| Сеансы | случайный токен, в базе хранится только его хеш; сеанс живёт 12 часов; при смене пароля, блокировке или смене роли все сеансы пользователя закрываются |
| Права | учитель — только замены (и только свои); всё остальное — только администратор; нельзя удалить или разжаловать последнего администратора |
| Проверка данных | каждое поле проверяется на сервере (типы, длина, допустимые значения, существование класса/учителя, даты не в прошлом, свободное время для переноса); сообщения об ошибках — на русском |
| Прочее | заголовки `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`; служба работает от отдельного пользователя без прав на изменение системы |

Рекомендации: давайте каждому учителю свою учётную запись, используйте длинные пароли,
блокируйте учётные записи уволившихся сотрудников («Настройки» → «Пользователи»).

## 8. Настройки

Файл `.env` в папке проекта (образец — `.env.example`):

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `SCHOOL_TZ` | `Europe/Moscow` | Часовой пояс школы — от него зависит, какой день «сегодня». Например: `Asia/Yekaterinburg`, `Asia/Novosibirsk`, `Europe/Samara` |
| `DB_PATH` | `data/schedule.db` | Где хранить базу |
| `COOKIE_SECURE` | `auto` | `auto` — защищённая cookie при работе по HTTPS; `1` — всегда; `0` — никогда |
| `SESSION_HOURS` | `12` | Сколько часов действует вход в панель |

Название школы, учебные дни и звонки меняются в панели: «Настройки» → «Школа и звонки».

## 9. Частые вопросы

**Сайт пишет «Слишком много неудачных попыток входа».** Подождите 15 минут или выполните
`python manage.py reset-password --username <логин>` (на сервере:
`cd /opt/school-schedule && sudo -u schedule .venv/bin/python manage.py reset-password --username <логин>`).

**Не получается войти на своём компьютере, хотя пароль верный.** Проверьте, что в `.env` нет `COOKIE_SECURE=1`
(для `http://127.0.0.1` нужно `auto` или `0`).

**Как добавить субботу?** Панель → «Настройки» → «Школа и звонки» → отметьте «Сб» → «Сохранить», затем заполните
расписание на субботу во вкладке «Расписание».

**Ученики видят старое расписание.** Страница обновляется сама раз в минуту и при возвращении на неё;
можно потянуть страницу вниз или нажать «Обновить» в браузере. Время последнего изменения указано под названием школы.

**Как удалить пример данных?** Остановите сайт, удалите файлы `data/schedule.db*`, выполните
`python manage.py init-db` и `python manage.py create-admin` (на сервере — через `sudo -u schedule`, см. шаг 6),
запустите сайт снова.
